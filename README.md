# Stellar Portfolio Rebalancer — Frontend

Next.js (App Router) + TypeScript + Tailwind dashboard for a non-custodial
DeFi portfolio rebalancer on Stellar. Talks directly to the deployed
[Soroban contracts](../contracts) for both reads and writes — there is no
backend API yet.

See [`../PROJECT.md`](../PROJECT.md) for the full project plan.

## Features

- **`/`** — marketing / landing page.
- **`/app`** — wallet-gated dashboard: connect a wallet (Freighter, Rabet,
  xBull, and others via Stellar Wallets Kit), view live allocation and
  drift read directly from the deployed `vault` contract, and
  deposit/withdraw/set targets.
- **`/demo`** — a fully client-side simulated $10,000 portfolio (no
  wallet, no chain, no backend) for exploring the product without funds.
  Uses the same allocation math as the on-chain contract, so the
  visualization behaves identically to the live dashboard.

## Architecture

| Path | Purpose |
|---|---|
| `src/contracts/` | TypeScript clients generated by `stellar contract bindings typescript`. **Generated — do not hand-edit** (excluded from ESLint). See [Regenerating contract bindings](#regenerating-contract-bindings). |
| `src/lib/stellar/` | Network config, contract client factories, and the Stellar Wallets Kit wrapper. |
| `src/hooks/` | `useWallet`, plus TanStack Query hooks (`useAllocation`, `useNeedsRebalance`, `useDeposit`, `useWithdraw`) that call the generated contract clients directly. |

### Regenerating contract bindings

Needed whenever a contract is redeployed to a new address:

```sh
stellar contract bindings typescript --contract-id vault --network testnet \
  --output-dir src/contracts/vault --overwrite
# then move src/contracts/vault/src/index.ts -> src/contracts/vault.ts
# and rm -rf src/contracts/vault (same pattern for oracle_adapter)
```

## Getting Started

Requires a Linux-native `node` (this project's `node_modules` won't run
under a Windows `node.exe` resolved via WSL interop) — install one via
[nvm](https://github.com/nvm-sh/nvm) and `nvm use` before running any
`npm`/`npx` command here.

```sh
npm install
npm run dev            # http://localhost:3000
```

## Testing

```sh
npm run lint
npx tsc --noEmit
npm run build
```

## Status

First slice built and verified live against Stellar testnet: wallet
connect, live allocation/drift chart, deposit/withdraw, `set_targets`,
and demo mode all working end-to-end, in both light and dark mode, with
no console or hydration errors. `src/contracts/vault.ts` is regenerated
against the current deployed address on every contract redeploy — see
[`../PROJECT.md`](../PROJECT.md) for the redeploy history.

No `/app/portfolios/[id]` routing yet (a single hardcoded portfolio), and
no backtest/simulate routes — both wait on the backend's `api` crate,
which doesn't exist yet.

# Stellar Portfolio Rebalancer — Frontend

Next.js (App Router) + TypeScript + Tailwind. See `../PROJECT.md` for the
full project plan.

## What's here

- **`/`** — landing page.
- **`/app`** — dashboard: connects a wallet (Freighter, Rabet, xBull, and
  others via Stellar Wallets Kit), reads live allocation/drift directly from
  the deployed testnet `vault` contract (no backend API involved for reads -
  those don't exist yet), and supports deposit/withdraw.
- **`src/contracts/`** — TypeScript clients generated by
  `stellar contract bindings typescript` against the deployed contracts.
  **Generated - don't hand-edit.** Regenerate with:
  ```sh
  stellar contract bindings typescript --contract-id vault --network testnet \
    --output-dir src/contracts/vault --overwrite
  # then move src/contracts/vault/src/index.ts -> src/contracts/vault.ts
  # and rm -rf src/contracts/vault (same for oracle_adapter)
  ```
  (excluded from ESLint in `eslint.config.mjs`.)
- **`src/lib/stellar/`** — network config, contract client factories, and
  the Stellar Wallets Kit wrapper.
- **`src/hooks/`** — `useWallet`, and TanStack Query hooks
  (`useAllocation`, `useNeedsRebalance`, `useDeposit`, `useWithdraw`) that
  call the generated contract clients directly.

No `api`/`scheduler` backend integration yet - this only talks to the chain.

## Build & test

```sh
npm run dev            # http://localhost:3000
npm run lint
npx tsc --noEmit
npm run build
```

## Status

First slice built and verified live against testnet: wallet connect,
live allocation/drift chart, deposit/withdraw. Screenshotted in both light
and dark mode with a headless browser; confirmed real 200s from
`soroban-testnet.stellar.org` and zero console/page errors (including a
hydration mismatch caused by Stellar Wallets Kit writing its own CSS vars
onto `<html>` on init - fixed with `suppressHydrationWarning` on that
element, the standard escape hatch for a third-party script mutating it
before hydration).

`vault` was later redeployed (Phase 2, to attach `risk_guard` - see
`../contracts/README.md`) and `src/contracts/vault.ts` regenerated
against the new address accordingly. `tsc --noEmit` and `eslint` both
pass clean against the regenerated bindings, but the browser
verification above predates that redeploy and hasn't been repeated
against it - environment constraints in the session that did the
redeploy meant `next dev` wasn't reachable to re-screenshot. Worth an
actual browser pass before calling this re-verified.

# Stellar Portfolio Rebalancer — Frontend

Next.js (App Router) + TypeScript + Tailwind dashboard for a non-custodial
DeFi portfolio rebalancer on Stellar. The legacy `/app` dashboard talks
directly to the deployed [Soroban contracts](../contracts) for both reads
and writes, no backend involved. `/app/portfolios` (sub-portfolios) also
talks to the [`rebalancer-api`](../backend) backend for
registration/listing/audit-log export, alongside direct-to-contract
deploy/initialize/write calls.

See [`../PROJECT.md`](../PROJECT.md) for the full project plan.

## Features

- **`/`** — marketing / landing page.
- **`/app`** — wallet-gated dashboard: connect a wallet (Freighter, Rabet,
  xBull, and others via Stellar Wallets Kit), view live allocation and
  drift read directly from the deployed `vault` contract, and
  deposit/withdraw/set targets.
- **`/demo`** — a fully client-side simulated $10,000 portfolio (no
  wallet, no chain, no backend) for exploring the product without funds.
  Uses the same allocation math as the on-chain contract, so the
  visualization behaves identically to the live dashboard.
- **`/app/portfolios`** — list the connected wallet's sub-portfolios (via
  `rebalancer-api`) and create a new one: deploys a fresh `vault`
  instance, `initialize`s it, authorizes the shared backend keeper via
  `set_keeper`, then registers it with the API — three wallet signatures,
  no partial state (registration is the last step).
- **`/app/portfolios/[id]`** — one sub-portfolio's dashboard: the same
  allocation/drift/deposit/withdraw/set-targets components as `/app`,
  pointed at that portfolio's own vault address, plus a CSV audit-log
  download.

## Architecture

| Path | Purpose |
|---|---|
| `src/contracts/` | TypeScript clients generated by `stellar contract bindings typescript`. **Generated — do not hand-edit** (excluded from ESLint). See [Regenerating contract bindings](#regenerating-contract-bindings). |
| `src/lib/stellar/` | Network config, contract client factories (`getVaultClient` takes an optional vault address override), and the Stellar Wallets Kit wrapper. |
| `src/lib/api/` | Thin `fetch` wrapper around `rebalancer-api` (`listPortfolios`, `getPortfolio`, `createPortfolio`, `reportCsvUrl`) — only used by `/app/portfolios`. Base URL from `NEXT_PUBLIC_API_URL` (see `.env.example`), defaults to `http://localhost:8080`. |
| `src/hooks/` | `useWallet`; TanStack Query hooks over the generated contract clients (`useAllocation`, `useNeedsRebalance`, `useDeposit`, `useWithdraw`, `useSetTargets` — each takes an optional `vaultAddress`, defaulting to the legacy hardcoded vault); `use-portfolios.ts`'s `usePortfolios`/`usePortfolio`/`useCreatePortfolio` (deploy → initialize → set_keeper → register). |

### Regenerating contract bindings

Needed whenever a contract is redeployed to a new address:

```sh
stellar contract bindings typescript --contract-id vault --network testnet \
  --output-dir src/contracts/vault --overwrite
# then move src/contracts/vault/src/index.ts -> src/contracts/vault.ts
# and rm -rf src/contracts/vault (same pattern for oracle_adapter)
```

## Getting Started

Requires a Linux-native `node` (this project's `node_modules` won't run
under a Windows `node.exe` resolved via WSL interop) — install one via
[nvm](https://github.com/nvm-sh/nvm) and `nvm use` before running any
`npm`/`npx` command here.

```sh
npm install
npm run dev            # http://localhost:3000
```

`/app/portfolios` additionally needs `rebalancer-api` running (see
[`../backend/README.md`](../backend/README.md#running-the-api)) and,
optionally, `NEXT_PUBLIC_API_URL` set if it's not on the default
`http://localhost:8080` — copy `.env.example` to `.env.local`.

## Status

First slice built and verified live against Stellar testnet: wallet
connect, live allocation/drift chart, deposit/withdraw, `set_targets`,
and demo mode all working end-to-end, in both light and dark mode, with
no console or hydration errors. `src/contracts/vault.ts` is regenerated
against the current deployed address on every contract redeploy — see
[`../PROJECT.md`](../PROJECT.md) for the redeploy history.

`/app/portfolios` and `/app/portfolios/[id]` (sub-portfolios: deploy →
initialize → set_keeper → register, list, per-portfolio dashboard, CSV
audit-log export) now built against `rebalancer-api` — `npm run lint`,
`tsc --noEmit`, and `npm run build` all pass, and both routes were
smoke-tested rendering via a local dev server (wallet-disconnected state:
no console/hydration errors). Not yet verified against a live wallet
actually deploying/initializing/registering a real vault end-to-end, or
against a running `rebalancer-api` instance — that needs a human with a
funded testnet wallet and Postgres running.

No backtest/simulate routes yet — those wait on backend work
(`rebalancer-backtest` is still CLI-only).
